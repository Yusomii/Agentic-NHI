# Agentic NHI: AI Code Generation Standards

This file defines the strict architectural and security constraints for any code generated by AI assistants (Gemini/Claude/Cursor) in this repository.

## 1. Architectural Constraints
- **Language:** Go (Golang) 1.22+.
- **Compilation:** Binaries must be statically linked. `CGO_ENABLED=0` is mandatory.
- **Containerization:** Multi-stage Docker builds only. The final runtime image MUST be `FROM scratch`. No OS packages permitted.
- **Infrastructure:** Terraform (HCL) version ~> 5.0.

## 2. Security & IAM (Zero-Trust)
- **Authentication:** GitHub Actions OIDC is the singular permitted AWS deployment mechanism. 
- **Secrets:** ABSOLUTELY NO static AWS Access Keys (`AWS_ACCESS_KEY_ID`) are to be hardcoded or requested.
- **Least Privilege:** Terraform IAM roles must strictly scope `Actions` and `Resources`. Wildcards (`*`) are prohibited in IAM policies.

## 3. Go Coding Standards
- **Error Handling:** Do not use `panic()`. Errors must be returned and wrapped using `fmt.Errorf("failed to [action]: %w", err)`.
- **Logging:** Use structured JSON logging (`log/slog`).
- **Layout:** Strictly adhere to the Standard Go Project Layout (`/cmd`, `/pkg`, `/internal`, `/infra`).

## 4. Operational Governance
- **Agentic Actions:** Any automated remediation (e.g., deleting a rogue IAM key) MUST implement a Human-in-the-Loop (HITL) approval gate via Slack Block Kit.
- **Bisection:** Commits must be logically separated (e.g., Infrastructure, Core Logic, Documentation).
